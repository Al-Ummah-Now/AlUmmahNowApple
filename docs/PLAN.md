# Apple apps: plan

Scope: viewer and Studio for iOS, iPadOS, tvOS, macOS. Spec: `docs/native-apps/EPICS.md` in the monorepo, §1–§4 and
Epics 12–23 and 30.

## 1. Workspace

One workspace, `AlUmmahNow.xcworkspace`, holding a project generated by XcodeGen from `project.yml` and five local
Swift packages. The `.xcodeproj` is not committed, so project merge conflicts cannot happen.

| Package | Contents | Depends on |
|---|---|---|
| `AUNCoreBridge` | Models, service protocols, temporary native services, fixtures | none |
| `AUNDesign` | Fanous tokens, `L10n`, `AppSettings`, shared components | CoreBridge |
| `AUNPlayer` | `PlayerController`, AVKit surfaces, WebVTT, Now Playing | CoreBridge, Design |
| `AUNFeatures` | Viewer screens and view-models for all platforms | all above |
| `AUNStudio` | Upload queue, encode queue, timeline, composition, live interface | CoreBridge, Design |

| App target | Platform | Bundle ID (proposed) |
|---|---|---|
| `ViewerIOS` | iPhone, iPad | `net.alummahnow.viewer` |
| `ViewerTV` | Apple TV | `net.alummahnow.viewer.tv` |
| `ViewerMac` | macOS | `net.alummahnow.viewer.mac` |
| `StudioIOS` | iPhone, iPad | `net.alummahnow.studio` |
| `StudioMac` | macOS | `net.alummahnow.studio.mac` |

QA builds append `.qa`, so both can be installed side by side. Minimum OS: iOS/tvOS 17, macOS 14 (Observation).

## 2. Architecture

- SwiftUI with Observation (`@Observable`, `@MainActor` view-models), async/await, Swift 6 language mode.
- App targets are thin: they build a `CoreBridge` and show a root view from a package.
- AppKit only for what SwiftUI does poorly on Mac: the editor timeline, Metal preview, window management.
- Logging through `os.Logger` (`AUNLog`), with no third-party telemetry until `aun-telemetry` (consent-gated).

### Seams for parallel work

| Dependency | Interim | Swap |
|---|---|---|
| `aun-core` / `aun-media` XCFramework | Protocols in `AUNCoreBridge` (`CatalogServicing`, `AuthSessionProviding`, `UploadEngine`, `EncodePlanning`, `EditDecisionList`), each with a native implementation | Add the binary target and one adapter per protocol; change `CoreBridge.temporaryNative` |
| Epic 9 backend | Public api-videos endpoints on QA | Regenerated client inside `aun-api` |
| Sign-in | Studio: `aun-auth` through `AUNCoreKit` (PKCE, several accounts, Keychain). Viewers: `GuestAuthSession` | Viewers adopt `AUNCoreKit` |
| Epic 10 tokens | `Fanous` placeholder values from spec §3 | Replace `FanousPalette` with the generated package |
| Fonts (D6) | System fonts (SF Arabic) | Add the licensed pair once decided |
| Live provider (D3) | `LiveBroadcasting` protocol, no ingest | Provider adapter, see `docs/research/live-broadcast.md` |

## 3. Testing

| Layer | Tool | Runs on |
|---|---|---|
| Logic and networking | Swift Testing with a stub `URLProtocol` | iOS, tvOS, macOS |
| Player | Swift Testing against a generated local video (no network) | iOS, tvOS, macOS |
| Views | swift-snapshot-testing, en + ar, dark + light; iOS 26.4 simulator only | iOS |
| Flows | XCUITest against fixtures (`-AUNUseFixtures YES`), en and ar, asserting RTL geometry | iPhone, iPad, Apple TV, macOS |
| Live QA | Guarded by `AUN_LIVE_QA=1`, run locally; CI stays hermetic | local |
| Static | SwiftLint (pinned), swift-format, L10n key parity, WCAG contrast of tokens | CI |

Snapshot references come from CI's toolchain (Xcode 26.6, iOS 26.4.1 simulator), because SwiftUI layout metrics differ slightly between Xcode versions. To update one, take the `failure_*` image from the `results-ios` artifact of a failing run, or record with `TEST_RUNNER_RECORD_SNAPSHOTS=1` under Xcode 26.6.

## 5. Release (not active until the owner provides an Apple Developer team)

`.github/workflows/release.yml` with `scripts/release.sh`, run only by GitHub Actions from a `vX.Y.Z` tag on a commit
on `main`: a notarized Mac download on the GitHub release, and TestFlight for iPhone and iPad. Uploading by hand is not
allowed. Without the owner's Apple secrets it builds unsigned artifacts. `docs/RELEASING.md` has the details.

## 6. Delivery order

1. Plan, scaffold, CI.
2. Core bridge and Fanous.
3. Viewer iOS and iPadOS: home rails, watch page, AVKit HLS, quality, speed, subtitles, PiP, background audio, AirPlay.
4. Viewer tvOS: focus engine, 10-foot home and player.
5. Viewer macOS.
6. Studio macOS: batch upload (TUS), VideoToolbox encode queue, AppKit/Metal timeline spike.
7. Studio iOS: AVFoundation edit spike, live-broadcast research behind an interface.

Later stories (accounts, library, offline, Listen, CarPlay, Kids, Islamic layer, notifications) follow the epics and
need Epic 9 sign-in.

## 7. Known interim behaviour

- **Rails**: `/api/videos/sections/*` omits `titleLocalized`, `channelName` and `uploadStatus`. The catalog service
  fetches each unique video's detail to fill them and to hide videos that are not ready.
- **Subtitles**: Bunny HLS manifests carry no subtitle renditions, and the API serves sidecar WebVTT. The player parses
  it and draws an overlay, which does not appear in PiP or on AirPlay until subtitles are muxed into the manifest.
